# Gibbon module conventions

Verified against Gibbon core v31.0.00 source and a live install (see skill `gibbon-live-testing`). When unsure, read
the core file (`tests/live/setup.sh` clones `GibbonEdu/core`) - do not guess an API. Items marked **LIVE** were
errors or facts observed in the running site, not read from source.

## Module shape
* Folder name = `$name` in `manifest.php`. Namespace = `Gibbon\Module\<name without non-alphanumerics>`; classes in
  `src/` are autoloaded PSR-4 (`src/Domain/XGateway.php` -> `Gibbon\Module\ServiceDesk\Domain\XGateway`).
  Project rule: no space in the module name.
* Pages and process scripts are flat files in the module root. Gibbon's file naming: `thing_manage.php` (list),
  `thing_manage_edit.php` (here: add when no id, edit with id), `thing_manage_editProcess.php`,
  `thing_manage_delete.php` (confirmation, opened in a modal) + `thing_manage_deleteProcess.php`.
* `version.php` (`$moduleVersion`), `manifest.php` (`$version`) and the newest `CHANGEDB.php` entry must carry the
  same number (`tests/static.php` checks it).
* Layers: SQL only in `src/Domain/*Gateway.php`; rules and multi-step logic in `src/Service/*`; pages build
  `Form`/`DataTable` and render Twig templates; process scripts check, call a service/gateway, redirect.

## Database
* Project rule: table names start with `gibbon` + module (`gibbonServiceDeskTicket`); primary key = table name + `ID`.
* `manifest.php`: every `$moduleTables[]` entry is executed separately -> one `CREATE TABLE` or one `INSERT` per
  entry. Seed with explicit ids when rows reference each other. manifest.php is PHP: loops are fine (the default
  workflow is generated by one). Use `$actionRows[] =`, `$moduleTables[] =` (the installer iterates by index).
* `CHANGEDB.php`: one `$sql[$count]` per version, statements separated by `;end`. Never edit a released entry; add a
  version for every schema/action change and mirror it in `manifest.php`. A new action in an upgrade needs
  `INSERT INTO gibbonAction ...` and `INSERT INTO gibbonPermission ...`.
* Connection charset is utf8 (3 bytes): no emoji in seed data.
* **Ids are zero-filled strings** (`'00000001'`) when read from the database, plain (`1`) when typed in a URL.
  **LIVE**: `$rows[$_GET['id']]` on an array keyed by database ids finds nothing. Key lookup arrays with `intval()`
  and compare ids with `intval($a) === intval($b)`. Passing either form as a query binding is fine.
* Gateways: `extends QueryableGateway`, `use TableAware`, `private static $tableName, $primaryKey,
  $searchableColumns`. Free: `getByID`, `insert` (returns id), `update($id, $data)`, `delete`, `exists`,
  `unique($data, $uniqueKeys, $excludeID)`, `selectBy`. Raw SQL: `$this->db()->select|selectOne|insert|update|delete
  |statement($sql, $bindings)`; `selectOne` returns the single column when one is selected, else the row.
  Result helpers: `fetchAll()`, `fetchKeyPair()`, `fetchGroupedUnique()`, `toDataSet()`.
* PDO named placeholders must be unique within a statement.
* Paginated lists: `$this->newQuery()->from()->cols()->innerJoin()->where()->bindValue()` + `runQuery($query,
  $criteria)`; filters via `$criteria->addFilterRules(['name' => fn($query, $value) => ...])` and
  `$criteria->filterBy('name', 'value')` (multi values: join with commas and use `FIND_IN_SET`).
* **LIVE**: inside the query builder's `where()`, `CAST(col AS UNSIGNED)` fails ("Unknown data type UNSIGNED": the
  builder treats `AS` as an alias). Use `col+0`. In raw SQL strings CAST is fine.
* **Queries do not throw**: `Connection::run` catches `PDOException`, raises a PHP warning and returns an empty
  result. After a write that matters, check the returned id / re-read the data.
* Transactions: `$db->beginTransaction()`, `commit()`, `rollBack()` on `Gibbon\Contracts\Database\Connection`
  (not nested: an inner begin is ignored).

## Container and services
* `$container->get(SomeClass::class)` autowires constructor arguments by type: gateways, other module services,
  `Gibbon\Contracts\Database\Connection`, `Gibbon\Contracts\Services\Session`, `Gibbon\Contracts\Comms\Mailer`,
  core gateways.
* **LIVE**: it cannot inject `Psr\Container\ContainerInterface` ("Alias ... is not being managed by the container").
  Where the container itself is needed, use `global $container` (core does the same).
* Globals available in pages and process scripts: `$guid, $connection2 (PDO), $pdo (Connection), $session,
  $container, $page, $gibbon`.

## Actions (manifest `$actionRows`)
* One entry per menu item; `URLList` lists every page and process script that belongs to it; `entryURL` the landing
  page; `category` groups the module menu. `defaultPermission{Admin,Teacher,Student,Parent,Support}` and
  `categoryPermission{Staff,Student,Parent,Other}` - both must allow a role.
* A page missing from every `URLList` cannot be opened by anyone (`tests/static.php` checks this).

## Pages
```php
if (isActionAccessible($guid, $connection2, '/modules/ServiceDesk/page.php') == false) {
    $page->addError(__('You do not have access to this action.'));
    return;
}
$page->breadcrumbs->add(__m('Parent'), 'parent.php', ['id' => $id])->add(__m('This Page'));
```
* Forms: `Form::create($id, $session->get('absoluteURL').'/modules/ServiceDesk/xProcess.php')` adds CSRF token and
  nonce; add `$form->addHiddenValue('address', $session->get('address'))`. Never write a raw `<form method=post>`.
  Small inline buttons (per-row remove, delete filter): `Form::createBlank($uniqueID, $action)` + hidden values +
  `addSubmit()` - **LIVE**: works inside a DataTable column and above a table.
* GET filter forms: `Form::createSearch()`, `$form->setClass('noIntBorder w-full')`,
  `addHiddenValue('q', '/modules/ServiceDesk/page.php')`, last row `addSearchSubmit($session, __('Clear Filters'))`.
  Never name a field `q`.
* Element facts (**LIVE**, v31): `addDate()` renders `<input type="date">` and posts `Y-m-d`
  (`Format::dateConvert()` returns such a value unchanged and never fails - validate with `checkdate`);
  `addYesNo()` renders a toggle backed by a hidden input posting `Y`/`N`; `addCheckbox($name)->fromArray()` posts
  `name[]`; `addSelect()->selectMultiple()` posts `name[]`; `->placeholder()` adds the empty first option.
* People pickers that query the database (`addSelectStudent`, `addSelectUsers`, `addSelectStaff`) need
  `$form->setFactory(DatabaseFormFactory::create($pdo))`. Without it the call returns an error placeholder and the
  next chained call dies with "Undefined Method ... on Layout\Element". **LIVE**: `addSelectStudent($name,
  $gibbonSchoolYearID)->selectMultiple()` works with the factory set. For a custom list use
  `addSelect($name)->fromArray($people)`.
* Show/hide rows: `$form->toggleVisibilityByClass('cls')->onSelect('field')->when('Value')` + `$row->addClass('cls')`.
* Edit forms: `$form->loadAllValuesFrom($values)` after adding the rows.
* Tables: `DataTable::createPaginated($id, $criteria)` + gateway result, or `DataTable::create($id)` +
  `->render($result->toDataSet())` / an array. `addHeaderAction('add', __('Add'))->setURL()->addParam()
  ->displayLabel()`; `addActionColumn()->addParam('id')->format(fn($row, $actions) => $actions->addAction('edit',
  __('Edit'))->setURL(...))`. An action named `delete` opens its URL in a modal: the target page prints
  `DeleteForm::createForm($processURL)` + hidden id. Row styling: `$table->modifyRows(fn($row, $tr) =>
  $tr->addClass('error'))`. `Format::using('yesNo', 'column')` exists (**LIVE**).
* Custom return messages: `$page->return->addReturns(['error4' => __m('...')])` on the page the process redirects to.
* Twig views: files in `templates/` are found by name: `echo $page->fetchFromTemplate('x.twig.html', $data)`.
  Twig autoescapes; available functions: `__`, `__m`, `__n`, `formatUsing('dateTimeReadable', value)`, `icon`.
* CSS: `$page->stylesheets->add('serviceDesk', 'modules/ServiceDesk/css/module.css')`. Use own class names
  (`serviceDesk-*`) rather than relying on theme utility classes.
* Role category of the current role: `$session->get('gibbonRoleIDCurrentCategory')` (Staff / Student / Parent /
  Other). Person: `gibbonPersonID`. School year: `gibbonSchoolYearID`.
* **LIVE (cosmetic)**: in Playwright *full-page* screenshots the submit row of a form appears to cover the first
  form row. It is an artefact of sticky positioning; check layout with a tall viewport screenshot instead.

## Process scripts
```php
require_once '../../gibbon.php';
$_POST = $container->get(Validator::class)->sanitize($_POST);      // strips tags; pass allowed HTML fields if any
$URL = $session->get('absoluteURL').'/index.php?q=/modules/ServiceDesk/page.php';
if (isActionAccessible($guid, $connection2, '/modules/ServiceDesk/page.php') == false) {
    header("Location: {$URL}&return=error0"); exit;
}
// validate -> act -> header("Location: {$URL}&return=success0");
```
* The file name must end in `Process.php`: gibbon.php checks CSRF token + nonce only for such scripts.
* **A symlinked module folder breaks `require_once '../../gibbon.php'`** (resolved from the real path). Copy the
  module into `modules/` (see `tests/live/sync.sh`).
* Return codes with built-in messages: `success0`, `error0` no access, `error1` invalid input, `error2` database,
  `error3` invalid, `error7` not unique, `warning1` partly saved.
* JSON posted in a hidden field: read it *before* `sanitize()` and clean it with your own whitelist.

## Translation (module level)
* Module text: `__m('Text')`, with parameters `__m('Hello {name}', ['name' => $x])`. Core text that Gibbon already
  translates ("Name", "Edit", "You do not have access to this action."): `__()`.
* Domain = module name; files `i18n/<locale>/LC_MESSAGES/ServiceDesk.mo`. Template: `php tests/make-pot.php`.
* Names stored in the database and shown to users (type names, labels, stage names) are also passed through `__m()`.

## Notifications
* Gibbon's `NotificationSender::addNotification()->sendNotifications()` writes the notification centre entry and
  emails it only if the person's global `receiveNotificationEmails` is on. For per-channel control (this module) use
  `NotificationGateway::selectNotificationByStatus / updateNotificationCount / insertNotification` for the centre and
  `Mailer` (`SetFrom`, `AddAddress`, `Subject`, `renderBody('mail/notification.twig.html', ['title', 'body',
  'button' => ['url', 'text']])`, `Send`) for email. Action link format:
  `/index.php?q=/modules/ServiceDesk/tickets_view.php&id=...`. Wrap in try/catch: never break the request.
* **LIVE**: the centre works when the row has `gibbonModuleID` of an installed module (the gateway looks it up by
  module *name*: it must be exactly `ServiceDesk`), `status='New'` and a link starting with `/index.php`. The bell
  count comes from `index_notification_ajax.php`; the list is `index.php?q=notifications.php`; "Action & Archive" is
  an htmx link to `notificationsActionProcess.php` which redirects to `absoluteURL + actionLink`.
* **LIVE**: email is sent only with a sender: `organisationEmail` (empty in the demo data) and the SMTP settings are
  read from the *session*, i.e. at login. Create the `Mailer` lazily (`global $container; $container->get(Mailer::
  class)`) and write all centre entries before sending any email.
* "Notifications do not work" checklist: (1) the actor is never notified - test with two users; (2) is the
  recipient a follower of the ticket or in a team of its type (empty teams -> administrators)? (3) the person's
  policy rows (`gibbonServiceDeskNotificationPreference`, `gibbonServiceDeskTicketSubscriber`); (4) rows in
  `gibbonNotification`; (5) PHP error log / `gibbonLog` title "Service Desk".

## Gibbon data used by this module
* Children of a parent: `gibbonFamilyAdult` (`childDataAccess='Y'`) -> `gibbonFamilyChild` -> `gibbonPerson`
  (`status='Full'`) + `gibbonStudentEnrolment` of the school year.
* Attendance: `gibbonAttendanceLogPerson` (code id, person, direction, type = code name, reason, context
  `Future`|`Person` for whole days, date, taker, timestampTaken); codes in `gibbonAttendanceCode` (`Absent`: direction
  Out); reasons in setting `Attendance/attendanceReasons`; school days via global `isSchoolOpen($guid, $date,
  $connection2)` (needs a term containing the date).
* Class enrolment: `gibbonCourseClassPerson.role` `Student` -> `Student - Left` + `dateUnenrolled`.
