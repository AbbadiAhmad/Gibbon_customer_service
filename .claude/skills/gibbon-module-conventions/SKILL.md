# Gibbon module conventions

Verified against Gibbon core v31.0.00 source and a live install (see skill `gibbon-live-testing`). When unsure, read
the core file (`tests/live/setup.sh` clones `GibbonEdu/core`) - do not guess an API. Items marked **LIVE** were
errors or facts observed in the running site, not read from source.

## Module shape
* Folder name = `$name` in `manifest.php`. Namespace = `Gibbon\Module\<name without non-alphanumerics>`; classes in
  `src/` are autoloaded PSR-4 (`src/Domain/XGateway.php` -> `Gibbon\Module\ServiceDesk\Domain\XGateway`).
  Project rule: no space in the module name.
* Pages and process scripts are flat files in the module root. Gibbon's file naming: `thing_manage.php` (list),
  `thing_manage_edit.php` (here: add when no id, edit with id), `thing_manage_editProcess.php`,
  `thing_manage_delete.php` (confirmation, opened in a modal) + `thing_manage_deleteProcess.php`.
* `version.php` (`$moduleVersion`), `manifest.php` (`$version`) and the newest `CHANGEDB.php` entry must carry the
  same number (`tests/static.php` checks it).
* Layers: SQL only in `src/Domain/*Gateway.php`; rules and multi-step logic in `src/Service/*`; pages build
  `Form`/`DataTable` and render Twig templates; process scripts check, call a service/gateway, redirect.

## Database
* Project rule: table names start with `gibbon` + module (`gibbonServiceDeskTicket`); primary key = table name + `ID`.
* `manifest.php`: every `$moduleTables[]` entry is executed separately -> one `CREATE TABLE` or one `INSERT` per
  entry. Seed with explicit ids when rows reference each other. manifest.php is PHP: loops are fine (the default
  workflow is generated by one). Use `$actionRows[] =`, `$moduleTables[] =` (the installer iterates by index).
* `CHANGEDB.php`: one `$sql[$count]` per version, statements separated by `;end`. Never edit a released entry; add a
  version for every schema/action change and mirror it in `manifest.php`. A new action in an upgrade needs
  `INSERT INTO gibbonAction ...` and `INSERT INTO gibbonPermission ...`.
* Connection charset is utf8 (3 bytes): no emoji in seed data.
* **Ids are zero-filled strings** (`'00000001'`) when read from the database, plain (`1`) when typed in a URL.
  **LIVE**: `$rows[$_GET['id']]` on an array keyed by database ids finds nothing. Key lookup arrays with `intval()`
  and compare ids with `intval($a) === intval($b)`. Passing either form as a query binding is fine.
* Gateways: `extends QueryableGateway`, `use TableAware`, `private static $tableName, $primaryKey,
  $searchableColumns`. Free: `getByID`, `insert` (returns id), `update($id, $data)`, `delete`, `exists`,
  `unique($data, $uniqueKeys, $excludeID)`, `selectBy`. Raw SQL: `$this->db()->select|selectOne|insert|update|delete
  |statement($sql, $bindings)`; `selectOne` returns the single column when one is selected, else the row.
  Result helpers: `fetchAll()`, `fetchKeyPair()`, `fetchGroupedUnique()`, `toDataSet()`.
* PDO named placeholders must be unique within a statement.
* Paginated lists: `$this->newQuery()->from()->cols()->innerJoin()->where()->bindValue()` + `runQuery($query,
  $criteria)`; filters via `$criteria->addFilterRules(['name' => fn($query, $value) => ...])` and
  `$criteria->filterBy('name', 'value')` (multi values: join with commas and use `FIND_IN_SET`).
* **LIVE**: inside the query builder's `where()`, `CAST(col AS UNSIGNED)` fails ("Unknown data type UNSIGNED": the
  builder treats `AS` as an alias). Use `col+0`. In raw SQL strings CAST is fine.
* **Queries do not throw**: `Connection::run` catches `PDOException`, raises a PHP warning and returns an empty
  result. After a write that matters, check the returned id / re-read the data.
* Transactions: `$db->beginTransaction()`, `commit()`, `rollBack()` on `Gibbon\Contracts\Database\Connection`
  (not nested: an inner begin is ignored).

## Container and services
* `$container->get(SomeClass::class)` autowires constructor arguments by type: gateways, other module services,
  `Gibbon\Contracts\Database\Connection`, `Gibbon\Contracts\Services\Session`, `Gibbon\Contracts\Comms\Mailer`,
  core gateways.
* **LIVE**: it cannot inject `Psr\Container\ContainerInterface` ("Alias ... is not being managed by the container").
  Where the container itself is needed, use `global $container` (core does the same).
* Globals available in pages and process scripts: `$guid, $connection2 (PDO), $pdo (Connection), $session,
  $container, $page, $gibbon`.

## Actions (manifest `$actionRows`)
* One entry per menu item; `URLList` lists every page and process script that belongs to it; `entryURL` the landing
  page; `category` groups the module menu. `defaultPermission{Admin,Teacher,Student,Parent,Support}` and
  `categoryPermission{Staff,Student,Parent,Other}` - both must allow a role.
* A page missing from every `URLList` cannot be opened by anyone (`tests/static.php` checks this).
* **Permission variants of one page = grouped actions** (**LIVE**): a second action with the same `URLList`, the name
  `<Base name>_<suffix>` and a higher `precedence` (here `New Request_onBehalf`). `isActionAccessible()` passes for
  either; `getHighestGroupedAction($guid, '/modules/ServiceDesk/page.php', $connection2)` returns the name of the
  strongest one the current role holds - compare it to decide what to offer. The menu shows one entry.
  **It only works for one family per page**: when two families list the same page (here `Edit Comments_*` and
  `Change Comment Visibility_*` on `tickets_comment_edit.php`) it returns the strongest of both together. Query the
  family yourself: `TicketAccess::getActionLevel('Edit Comments')` -> `all` / `my` / ``. Actions without a menu
  entry: `menuShow` `N`.
* **LIVE** upgrade recipe for a new action (CHANGEDB): `INSERT INTO gibbonAction (gibbonModuleID, name, precedence,
  category, description, URLList, entryURL, entrySidebar, menuShow, defaultPermission*, categoryPermission*) VALUES
  ((SELECT gibbonModuleID FROM gibbonModule WHERE name='ServiceDesk'), ...);end` then `INSERT INTO gibbonPermission
  (gibbonRoleID, gibbonActionID) SELECT gibbonRole.gibbonRoleID, gibbonAction.gibbonActionID FROM gibbonRole JOIN
  gibbonAction ON (gibbonAction.name='...') JOIN gibbonModule ON (... AND gibbonModule.name='ServiceDesk') WHERE
  gibbonRole.name IN ('Administrator', ...)`. Permissions and the menu are read at login: log in again to see them.

## Pages
```php
if (isActionAccessible($guid, $connection2, '/modules/ServiceDesk/page.php') == false) {
    $page->addError(__('You do not have access to this action.'));
    return;
}
$page->breadcrumbs->add(__m('Parent'), 'parent.php', ['id' => $id])->add(__m('This Page'));
```
* Forms: `Form::create($id, $session->get('absoluteURL').'/modules/ServiceDesk/xProcess.php')` adds CSRF token and
  nonce; add `$form->addHiddenValue('address', $session->get('address'))`. Never write a raw `<form method=post>`.
  Small inline buttons (per-row remove, delete filter): `Form::createBlank($uniqueID, $action)` + hidden values +
  `addSubmit()` - **LIVE**: works inside a DataTable column and above a table.
* GET filter forms: `Form::createSearch()`, `$form->setClass('noIntBorder w-full')`,
  `addHiddenValue('q', '/modules/ServiceDesk/page.php')`, last row `addSearchSubmit($session, __('Clear Filters'))`.
  Never name a field `q`.
* Element facts (**LIVE**, v31): `addDate()` renders `<input type="date">` and posts `Y-m-d`
  (`Format::dateConvert()` returns such a value unchanged and never fails - validate with `checkdate`);
  `addYesNo()` renders a toggle backed by a hidden input posting `Y`/`N`; `addCheckbox($name)->fromArray()` posts
  `name[]`; `addSelect()->selectMultiple()` posts `name[]`; `->placeholder()` adds the empty first option.
* People pickers that query the database (`addSelectStudent`, `addSelectUsers`, `addSelectStaff`) need
  `$form->setFactory(DatabaseFormFactory::create($pdo))`. Without it the call returns an error placeholder and the
  next chained call dies with "Undefined Method ... on Layout\Element". **LIVE**: `addSelectStudent($name,
  $gibbonSchoolYearID)->selectMultiple()` works with the factory set. For a long custom list of people use
  `addSelectPerson($name)->fromArray($people)->placeholder()` (searchable; **LIVE** with 1000+ people). For a custom list use
  `addSelect($name)->fromArray($people)`.
* Show/hide rows: `$form->toggleVisibilityByClass('cls')->onSelect('field')->when('Value')` + `$row->addClass('cls')`.
* Edit forms: `$form->loadAllValuesFrom($values)` after adding the rows. **LIVE bug**: it overrides `->checked()` /
  `->selected()` for every field named in `$values`. A checkbox group or multi-select stored as comma-separated text
  must be given as an array (`$values['x'] = explode(',', $values['x'])`), otherwise nothing is ticked and the next
  save silently empties the column. Test every edit form by saving it twice without changes.
* Tables: `DataTable::createPaginated($id, $criteria)` + gateway result, or `DataTable::create($id)` +
  `->render($result->toDataSet())` / an array. `addHeaderAction('add', __('Add'))->setURL()->addParam()
  ->displayLabel()`; `addActionColumn()->addParam('id')->format(fn($row, $actions) => $actions->addAction('edit',
  __('Edit'))->setURL(...))`. An action named `delete` opens its URL in a modal: the target page prints
  `DeleteForm::createForm($processURL)` + hidden id. Row styling: `$table->modifyRows(fn($row, $tr) =>
  $tr->addClass('error'))`. `Format::using('yesNo', 'column')` exists (**LIVE**).
* Custom return messages: `$page->return->addReturns(['error4' => __m('...')])` on the page the process redirects to.
* **LIVE - template cache**: Gibbon compiles Twig templates into `uploads/cache/templates` and does not notice a
  changed file (unless System setting `installType` is Development). After editing a `.twig.html` the page keeps its
  old output: empty that folder (`tests/live/sync.sh` does) / System Admin > Cache Manager on a real site. Symptom:
  the PHP page passes new data, the HTML does not change.
* Twig views: files in `templates/` are found by name: `echo $page->fetchFromTemplate('x.twig.html', $data)`.
  Twig autoescapes; available functions: `__`, `__m`, `__n`, `formatUsing('dateTimeReadable', value)`, `icon`.
* JavaScript: `$page->scripts->add('serviceDeskBoard', 'modules/ServiceDesk/js/board.js')` (**LIVE**). Gibbon swaps
  page content with htmx: attach listeners to `document` (event delegation) and guard against loading twice.
* **LIVE - changes from JavaScript without AJAX**: put a hidden `Form::createBlank('id', $processURL)` with
  `addHiddenValue()` fields on the page; the script fills the fields and calls `form.submit()`. The request carries
  Gibbon's CSRF token and nonce and the process script redirects back as usual (used by the board's drag and drop).
* **LIVE - wide content**: a flex row with min-width columns widens the whole Gibbon page. Wrap it in
  `display:grid; grid-template-columns:minmax(0,1fr)` and give the row `overflow-x:auto`.
* `addColor($name)` renders a colour input posting `#rrggbb` (**LIVE**); validate with a regex before storing and
  before printing it into a `style` attribute.
* Lists without paging: `newQueryCriteria(false)->pageSize(300)`; result `->toArray()`.
* A page fragment must not be a second file in the module root (every root `.php` is an entry point and must be in
  an action): keep it inside its page or in `src/`.
* CSS: `$page->stylesheets->add('serviceDesk', 'modules/ServiceDesk/css/module.css')`. Use own class names
  (`serviceDesk-*`) rather than relying on theme utility classes.
* Role category of the current role: `$session->get('gibbonRoleIDCurrentCategory')` (Staff / Student / Parent /
  Other). Person: `gibbonPersonID`. School year: `gibbonSchoolYearID`.
* **LIVE (cosmetic)**: in Playwright *full-page* screenshots the submit row of a form appears to cover the first
  form row. It is an artefact of sticky positioning; check layout with a tall viewport screenshot instead.

## Process scripts
```php
require_once '../../gibbon.php';
$_POST = $container->get(Validator::class)->sanitize($_POST);      // strips tags; pass allowed HTML fields if any
$URL = $session->get('absoluteURL').'/index.php?q=/modules/ServiceDesk/page.php';
if (isActionAccessible($guid, $connection2, '/modules/ServiceDesk/page.php') == false) {
    header("Location: {$URL}&return=error0"); exit;
}
// validate -> act -> header("Location: {$URL}&return=success0");
```
* The file name must end in `Process.php`: gibbon.php checks CSRF token + nonce only for such scripts.
* **A symlinked module folder breaks `require_once '../../gibbon.php'`** (resolved from the real path). Copy the
  module into `modules/` (see `tests/live/sync.sh`).
* Return codes with built-in messages: `success0`, `error0` no access, `error1` invalid input, `error2` database,
  `error3` invalid, `error7` not unique, `warning1` partly saved.
* JSON posted in a hidden field: read it *before* `sanitize()` and clean it with your own whitelist.

## Translation (module level)
* Module text: `__m('Text')`, with parameters `__m('Hello {name}', ['name' => $x])`. Core text that Gibbon already
  translates ("Name", "Edit", "You do not have access to this action."): `__()`.
* Domain = module name; files `i18n/<locale>/LC_MESSAGES/ServiceDesk.mo`. Template: `php tests/make-pot.php`.
* Names stored in the database and shown to users (type names, labels, stage names) are also passed through `__m()`.

## Lists that stay fast with many rows (**LIVE**, measured with 200 000 tickets - `docs/AUDIT.md`)
* `runQuery()` uses `SQL_CALC_FOUND_ROWS` and so always evaluates the whole matching set; with joins to names and labels
  that costs seconds. **Find the page first, then load details**: step 1 = `runQuery()` on a narrow query (the main
  table + what filters and sorting need), step 2 = one `SELECT ... WHERE id IN (...)` with the joins for the 25 ids;
  return `(new DataSet($rows))->setResultCount($page->getResultCount(), $page->getTotalCount())->setPagination(
  $criteria->getPage(), $criteria->getPageSize())`. `DataTable::createPaginated` works with that unchanged.
* Give step 1 a **covering index**: all columns it filters, sorts and selects, led by the column most filters use (here
  the stage; a second one led by the type). Then it never reads the wide rows (JSON, text). Do not select big text
  columns in lists.
* Turn conditions on small tables into **id lists computed in PHP** (`stage IN (ids of open stages)`, ids of people
  matching a search word, the family, the team's types) instead of joins, sub-selects, `FIND_IN_SET(col+0, ...)` or
  `OR` across tables: each of those forces a full scan. Ids go through `intval` (`TicketGateway::ids`) before they are
  written into `IN (...)`.
* Join person tables in step 1 only when the list is sorted by a name (`$criteria->hasSort('requester.surname')`).
* `LIKE '%word%'` cannot use an index: keep one search text per row (here answers + public comments, maintained by
  `TicketService::refreshSearchText`) rather than searching child tables, and expect time to grow with the rows the
  person may see.
* **The browser can post its own criteria** to any page with a Gibbon table (`fromPOST()` takes `sortBy`, `pageSize`,
  `page`, `filterBy`): Gibbon escapes the sort column but accepts any column of the query's tables, and any page size.
  In the gateway keep only your own sort columns (`array_intersect_key($criteria->getSortBy(), ...)` +
  `$criteria->fromArray(['sortBy' => ...])`) and clamp the page size. Posted `filterBy` only reaches your filter rules;
  posted `searchBy` only columns in `$searchableColumns`.
* Deleting or checking per row against a core table without a fitting index (`gibbonNotification` has only the person
  index) is a full scan each time: batch it (`text REGEXP '^#(1|2|3) '` once per 500 tickets).
* Measure with `tests/perf/seed.sql` + `tests/perf/measure.js` (page time, database time, rows read, slowest query)
  before and after; `ANALYZE TABLE` after bulk loads or new indexes.
* MariaDB's `seq_1_to_N` tables generate test rows fast; zero-filled ids put into text must be written `id+0`.

## "Changed since I last looked" (unread marks)
* One row per person per record with `timestampSeen` (`gibbonServiceDeskTicketSeen`), written when the record's page is
  opened (and after the person's own actions that do not end on that page, e.g. a board move). In the list query LEFT JOIN
  it for the current person and compute a column (`unread`) so it can be shown **and sorted by**
  (`$criteria->sortBy('unread', 'DESC')->sortBy('timestampModified', 'DESC')->sortBy('table.id', 'DESC')` - `sortBy` can
  be called several times; add the id as a tie-break, timestamps have one-second resolution).
* Keep a second timestamp for "last change the requester can read" when some changes are internal, otherwise people are
  alerted by things they cannot see.
* On upgrade insert "seen now" rows for the people involved, or every old record lights up.
* `DataTable::createPaginated` columns are sortable by clicking the heading out of the box (**LIVE**), also computed ones.

## Lists stored as comma-separated text
* `Stage.automation`, `TicketType.roleCategories`: store `implode(',', ...)` of **validated** keys in a fixed order
  (`array_intersect($allKeysInOrder, $posted)`); read with `array_filter(explode(',', $value))`; edit with
  `addCheckbox($name)->fromArray($options)` and give `loadAllValuesFrom()` the array, never the text (see the LIVE bug
  above). Unknown keys read from the database are skipped, not fatal.
* Dropping a column in CHANGEDB: migrate its meaning first (`UPDATE ... WHERE oldColumn='Y'`), then `ALTER TABLE ... DROP`,
  as separate `;end` statements in that order (1.6.00 is the example).

## Dashboard hooks, CLI scripts, plain gateways
* **Dashboard hook** (**LIVE**): `$hooks[]` in `manifest.php` / an INSERT in CHANGEDB:
  `INSERT INTO gibbonHook (name, type, options, gibbonModuleID) VALUES ('Service Desk', 'Parental Dashboard' | 'Staff Dashboard',
  serialize(['sourceModuleName' => 'ServiceDesk', 'sourceModuleAction' => 'Tickets', 'sourceModuleInclude' => 'hook_x.php']), (SELECT
  gibbonModuleID ...))`. In CHANGEDB build the serialized string in PHP (`serialize()` inside the file; the double quotes in it
  are fine inside a single-quoted SQL string). Gibbon `include`s the file from inside the dashboard class and uses
  its **return value** as the tab content; the tab label is the hook name. Roles holding the named action get the tab.
  The file runs in a method scope: `global $container, $session, $page;`. **The dashboard is not a page of the module, so
  the module's classes are not autoloadable yet** (error "Alias ... is not being managed by the container"): call
  `$container->get(\Gibbon\Services\ModuleLoader::class)->registerModuleNamespace('ServiceDesk');` first. Add the module
  stylesheet with `$page->stylesheets->add(...)`. A tab for which Gibbon has no icon still renders.
* **A box in the home page sidebar without touching core** (**LIVE**, v31): inside a dashboard hook set
  `$session->set('sidebarExtra', $html)` and `$session->set('sidebarExtraPosition', 'bottom')` (below the Message Wall
  and the other sidebar boxes; `'top'` is the default). `index.php` moves that session value into the sidebar after the
  dashboard is built. Do **not** also call `$page->addSidebarExtra()`: with position `bottom` the template prints every
  entry, including Gibbon's own empty one, and an empty second box appears.
* **A hook always produces a tab** (the tab template prints every tab, also an empty one; parents get it once per
  child, and the include file has the child's `$gibbonPersonID` in scope). To have no tab, return a marker plus an
  inline script that removes its own `[role=tabpanel]` and the `[role=tab]` button with the same index
  (`DashboardWidget::hook`); keep a harmless fallback (a link) for a Gibbon whose markup differs. Guard work that must
  happen once per page with a static flag: the hook runs once per child for parents.
* A parent, staff and student hook can share one include file; a Student Dashboard hook exists too.
* **CLI script** (`cli_*.php`, **LIVE**): first statement `if (PHP_SAPI !== 'cli') { exit(...); }`, then `require_once
  __DIR__.'/../../gibbon.php';` (works from the shell with the module copied under `modules/`), then
  `$container->get(...)`. `$argv` for options. It needs no action in `manifest.php`; `tests/static.php` checks the
  first statement. Files named `cli_*` / `hook_*` are exempt from the "every root file is in an action" rule.
* A gateway without a table: `class XGateway extends Gibbon\Domain\Gateway` and use `$this->db()` (see `GuardianGateway`).
* Data kept as JSON on a row (ticket answers) cannot be searched reliably through the JSON: keep a plain-text copy
  (`searchText`) and, for rows from before the column existed, fall back with `COALESCE(searchText, fields)`.
* Several `where()` calls on one query are ANDed; bind every value with a unique placeholder name (`:searchA0`, `:searchA1`,
  ...) when the same condition is repeated per word.
* `addcslashes($word, '%_\\')` makes LIKE wildcards plain characters (MySQL's default escape is the backslash).
* `DataSet::getResultCount()` and `toArray()` give a short list together with the total (`pageSize(5)` on the criteria).
* `DELETE t FROM t JOIN other ... WHERE ...` (multi-table delete) works through `$this->db()->delete()`.

## Notifications
* Gibbon's `NotificationSender::addNotification()->sendNotifications()` writes the notification centre entry and
  emails it only if the person's global `receiveNotificationEmails` is on. For per-channel control (this module) use
  `NotificationGateway::selectNotificationByStatus / updateNotificationCount / insertNotification` for the centre and
  `Mailer` (`SetFrom`, `AddAddress`, `Subject`, `renderBody('mail/notification.twig.html', ['title', 'body',
  'button' => ['url', 'text']])`, `Send`) for email. Action link format:
  `/index.php?q=/modules/ServiceDesk/tickets_view.php&id=...`. Wrap in try/catch: never break the request.
* **LIVE**: the centre works when the row has `gibbonModuleID` of an installed module (the gateway looks it up by
  module *name*: it must be exactly `ServiceDesk`), `status='New'` and a link starting with `/index.php`. The bell
  count comes from `index_notification_ajax.php`; the list is `index.php?q=notifications.php`; "Action & Archive" is
  an htmx link to `notificationsActionProcess.php` which redirects to `absoluteURL + actionLink`.
* **LIVE**: email is sent only with a sender: `organisationEmail` (empty in the demo data) and the SMTP settings are
  read from the *session*, i.e. at login. Create the `Mailer` lazily (`global $container; $container->get(Mailer::
  class)`) and write all centre entries before sending any email.
* **LIVE**: `Mailer::Send()` returns false and sets `$mail->ErrorInfo` on failure - it does not throw. Check the
  return value. `Notifier::sendTest()` (button on Notification Settings) reports both channels to the user.
* Messages for the next page after a redirect: `$session->set('key', $data)` in the process script, read and
  `$session->forget('key')` on the page.
* "Notifications do not work" checklist: (0) ask the user to press *Send Me a Test Notification*; (1) the actor is never notified - test with two users; (2) is the
  recipient a follower of the ticket or in a team of its type (empty teams -> administrators)? (3) the person's
  policy rows (`gibbonServiceDeskNotificationPreference`, `gibbonServiceDeskTicketSubscriber`); (4) rows in
  `gibbonNotification`; (5) PHP error log / `gibbonLog` title "Service Desk".

## Gibbon data used by this module
* Children of a parent: `gibbonFamilyAdult` (`childDataAccess='Y'`) -> `gibbonFamilyChild` -> `gibbonPerson`
  (`status='Full'`) + `gibbonStudentEnrolment` of the school year.
* Attendance: `gibbonAttendanceLogPerson` (code id, person, direction, type = code name, reason, context
  `Future`|`Person` for whole days, date, taker, timestampTaken); codes in `gibbonAttendanceCode` (`Absent`: direction
  Out); reasons in setting `Attendance/attendanceReasons`; school days via global `isSchoolOpen($guid, $date,
  $connection2)` (needs a term containing the date).
* Class enrolment: `gibbonCourseClassPerson.role` `Student` -> `Student - Left` + `dateUnenrolled`.

## Verifying
1. `php tests/static.php`.
2. A live run (`gibbon-live-testing`) for anything touching pages, forms, queries or permissions. `php -l` alone has
   missed every real bug so far. Say which of the two was done.
